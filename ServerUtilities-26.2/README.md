# Server Utilities — Minecraft 26.2

서버 공통 수면·전투·밸런스·사망 규칙을 관리하는 Fabric 모듈입니다. 기존 Jobs+의 전투·사망 처리와 Advanced Netherite의 크리퍼 피해·행동 피로도 보정을 이 모듈로 옮겼습니다.

## 설치

- Minecraft 26.2, Java 25, Fabric Loader 0.19.3 이상, Fabric API 0.154.2+26.2 이상이 필요합니다.
- 전용 서버의 `mods`에 설치합니다. 원격 접속 자체에는 클라이언트 설치가 필수가 아니지만, 방어도 30 초과·최대 체력 1,024 초과 속성값의 계산·표시와 장비 등급·도구 LV 툴팁을 서버와 일치시키려면 클라이언트에도 같은 버전을 설치합니다.
- 싱글플레이·LAN 호스트에서도 적용하려면 해당 클라이언트에 설치합니다. `environment: "*"`로 로드하며 게임 규칙은 서버에서만, 방어도·체력 속성 상한과 거래 횟수 제한 해제는 서버·클라이언트 공통으로 적용합니다.
- **이 작업에서 빌드한 Jobs+·Advanced Netherite·Server Utilities를 함께 교체하세요.** 이전 Jobs+·Advanced Netherite의 규칙 클래스가 발견되면 중복 적용을 막기 위해 기동을 중단합니다.
- Jobs+·Advanced Netherite·TACZ 등 기존 모드의 클라이언트 설치 요구는 그대로입니다.
- Server Utilities 자체는 Jobs+·Advanced Netherite·ArcLib·YamlConfig·UILib에 의존하지 않습니다. 보존권은 기존 아이템 ID로 찾아 사용하므로 Advanced Netherite가 없으면 보존권 소비 없이 설정된 사망 손실 정책을 적용합니다.

## 보스 체력과 공격

- 워든의 기본 최대 체력은 500 → 1,000, 위더는 300 → 600, 엔더 드래곤은 200 → 2,000입니다. 차원에 관계없이 신규 생성·기존 개체 로드 때 적용합니다.
- 기존 개체는 남은 체력 비율을 보존합니다. 변경된 기본값이 저장되므로 재시작·청크 재로드로 배율이 누적되지 않으며, 죽은 보스나 사망 비행 중인 드래곤을 회복시키지 않습니다.
- 위더의 소환 준비 중 회복량만 최대 체력에 비례해 늘려 정상 소환 완료 시 600 HP가 됩니다. 전투 중 자연 회복과 기존 소환수·탈출 규칙은 유지합니다.
- 워든을 추적하는 플레이어에게 파란색 바닐라 보스바를 표시합니다. 체력·이름을 갱신하고, 땅속으로 퇴장할 때 숨기며 사망·언로드·추적 종료·접속 종료 시 정리합니다.
- 엔더 드래곤은 기존 화염구 발사 타이밍에 중앙 1발, 좌우 각 12도·상하 각 8도로 퍼지는 4발을 함께 발사합니다. 속도·가속도·발사 주기와 이후 행동 전환은 유지하며, 각 탄환은 바닐라 브레스 장판을 생성합니다.
- `minecraft:max_health`의 허용 상한을 1,024 → 2,048로 확장합니다. 허용 상한은 모든 생명체에 공통이며 실제 기본 체력 변경은 위 세 보스에 한정합니다. 서버·클라이언트에 같은 버전을 설치하고 재시작해야 합니다.
- Jobs+의 드래곤 업적 기여도 5% 조건은 100 피해가 됩니다. 마지막일격 칭호는 기존 마지막 타격 판정을 사용합니다. HP 증가만으로 솔로 공략 불가능이 보장되는 것은 아니므로 실제 장비로 난이도를 확인해야 합니다.

## 자석석 설치 제한

- 새로 설치한 자석석은 플레이어당 한 개로 제한하며 설치자 UUID와 차원·좌표를 월드 데이터에 저장합니다. 기록 도입 전에 설치된 자석석은 추적하지 않습니다.
- Server Utilities `1.0.1`부터 재설치 시 기록된 위치의 실제 블록을 확인합니다. 폭발이나 명령어로 제거됐거나 이전 버전에서 잘못 남은 기록은 해제하고 재설치를 허용합니다. 기존 기록 파일을 삭제할 필요는 없습니다.
- 피스톤으로 밀거나 당기면 소유권도 목적지로 이동합니다. 피스톤 애니메이션 중에도 제한을 유지하며, 이동된 자석석을 채굴하거나 제거한 뒤에는 재설치를 허용합니다.
- 기록된 위치가 다른 차원이나 언로드된 청크에 있어도 실제 블록을 조회합니다. 청크가 로드되지 않았다는 이유만으로 소유권을 해제하지 않습니다.

## 방어도 상한 해제

바닐라는 방어도를 세 곳에서 제한합니다. 세 가지를 모두 처리해야 높은 방어도가 실제 피해 감소로 이어집니다.

### 속성 최대값

- `minecraft:armor`의 최대값을 30에서 1,024로 확장합니다. 모든 생명체의 해당 속성에 적용하며 아이템 자체의 방어도 수치를 변경하지 않습니다.
- 서리빛 네더라이트 방어구 4부위의 기본 방어도 합계 34를 속성값으로 사용할 수 있습니다.
- 속성 초기화 시 적용하는 고정값이므로 수정된 모드를 설치한 뒤 서버·클라이언트를 다시 시작해야 합니다. `/serverutilities reload`로 변경하지 않습니다.
- 방어도 생성 구간의 생성자 인자 하나만 수정하며, 대상이 없거나 둘 이상이면 Mixin 적용을 실패시켜 버전 변경으로 인한 오적용을 드러냅니다.

### 방어도 소수점

- 피해 계산에 넘기는 방어도를 정수로 내리지 않고 속성값 그대로 사용합니다. 등급별로 소수 방어도를 부여해도 계산에 반영됩니다.
- 방어 강도는 바닐라도 내리지 않으므로 그대로 둡니다. 방어 강도 상한 20도 유지합니다.
- HUD의 방어구 게이지는 바닐라 표현을 그대로 씁니다. 정확한 값은 `/attribute` 명령으로 확인합니다.

### 피해 감소 곡선

- 유효 방어도 상한 20을 없애고, 20을 넘는 구간의 피해 감소율을 `유효방어도 ÷ (유효방어도 + 5)`로 계산합니다.
- 두 구간은 유효 방어도 20에서 모두 80%를 내므로 경계에서 값이 튀지 않습니다.
- 방어도를 올릴수록 감소율은 계속 오르지만 증가폭은 줄어듭니다. 유한한 방어도로는 100%에 도달하지 않으므로 무적 상태가 생기지 않습니다.
- 방어 관통 피해, 보호 마법부여, 저항 효과의 기존 처리 순서는 바꾸지 않습니다. 방어 관통 태그가 붙은 피해는 이 계산 자체를 거치지 않습니다.
- 곡선의 완만함을 정하는 값은 경계 연속성 때문에 25에서 20을 뺀 값으로 고정되어 있습니다. 설정으로 열지 않습니다.
- `balance.armor.enabled`를 끄면 소수점 사용과 감소 곡선이 모두 바닐라 동작으로 돌아갑니다. 속성 최대값 확장은 이 설정과 무관하게 유지됩니다.

같은 조건에서 피해 20을 받을 때 풀세트별 피해 감소율입니다. 보호 마법부여와 저항 효과, 방어 관통이 없는 경우입니다.

| 풀세트 | 방어도 합계 | 변경 전 | 변경 후 |
|---|---|---|---|
| 네더라이트 | 20 | 64.00% | 64.00% |
| 잿빛 | 22 | 73.45% | 73.45% |
| 태양빛 | 26 | 80.00% | 81.93% |
| 영혼빛 | 30 | 80.00% | 84.34% |
| 서리빛 | 34 | 80.00% | 86.17% |

## 넉백 저항 재배치

넉백 저항은 방어구 부위마다 값이 더해지고 합계 상한이 1.0입니다. 1.0이면 넉백 완전 면역입니다. 기존 값으로는 상위 등급이 상한에 걸려 서로 구별되지 않았습니다.

| 재질 | 부위당 (변경 전) | 4부위 (변경 전) | 부위당 (변경 후) | 4부위 (변경 후) |
|---|---|---|---|---|
| 네더라이트 | 0.1 | 0.4 | 0.05 | 0.20 |
| 잿빛 | 0.1 | 0.4 | 0.06 | 0.24 |
| 태양빛 | 0.2 | 0.8 | 0.07 | 0.28 |
| 영혼빛 | 0.3 | 1.2, 1.0으로 잘림 | 0.08 | 0.32 |
| 서리빛 | 0.4 | 1.6, 1.0으로 잘림 | 0.09 | 0.36 |

- 변경 전에는 서리빛이 3부위만 착용해도 상한에 닿아 4번째 부위의 값이 버려졌고, 영혼빛 풀세트와 서리빛 풀세트가 넉백 면에서 같았습니다.
- 변경 후에는 모든 등급의 4부위 합계가 상한 아래에 있어 등급 차이가 그대로 드러납니다.
- 바닐라 네더라이트는 Mixin으로 낮춥니다. 네더라이트 생성 구간으로 한정하므로 다른 바닐라 재질은 바뀌지 않습니다.
- 속성 초기화 시 적용하는 고정값이라 `/serverutilities reload`로 바꾸지 않습니다. 강화 네더라이트 4종은 Advanced Netherite 소스의 선언값을 직접 고쳤습니다.

## 장비 등급

내구도가 있는 장비에 S부터 F까지 일곱 등급 중 하나를 무작위로 붙이고, 등급에 따라 수치를 낮춥니다. S는 아이템의 원래 수치와 같습니다.

| 등급 | 부여 확률 | 내구도 | 채굴 속도 | 공격력 | 방어도 |
|---|---|---|---|---|---|
| S | 14.29% | 100% | 100% | 100% | 100% |
| A | 14.29% | 93% | 96% | 96% | 96% |
| B | 14.29% | 86% | 92% | 92% | 92% |
| C | 14.29% | 79% | 88% | 88% | 88% |
| D | 14.29% | 72% | 84% | 84% | 84% |
| E | 14.29% | 65% | 80% | 80% | 80% |
| F | 14.29% | 58% | 76% | 76% | 76% |

### 부여 방식

- 등급이 없는 장비가 플레이어 인벤토리나 착용 칸에 있으면 그 자리에서 추첨해 붙입니다. 1초에 한 번 확인합니다.
- 제작, 구조물 상자, 상점, 랜덤박스, 명령 지급을 따로 연동하지 않아도 모든 경로가 덮입니다.
- 등급은 아이템의 커스텀 데이터에 기록하므로 저장과 클라이언트 동기화가 보장됩니다. 한 번 정해진 등급은 바뀌지 않습니다.
- 대상은 기본 최대 내구도가 있는 아이템입니다. 총기 탄약처럼 내구도가 없는 아이템에는 붙지 않습니다.

### 부위별 적용 범위

내구도는 모든 대상에 적용하고, 나머지는 부류에 따라 다릅니다.

| 부류 | 판정 기준 | 내구도 | 채굴 속도 | 공격력 | 방어도 |
|---|---|---|---|---|---|
| 굴착 도구 | 곡괭이, 도끼, 삽, 괭이 태그 | 적용 | 적용 | 미적용 | 미적용 |
| 근접 무기 | 굴착 도구가 아니면서 공격력이 있는 장비 | 적용 | 미적용 | 적용 | 미적용 |
| 방어구 | 머리, 몸통, 다리, 발 방어구 태그 | 적용 | 미적용 | 미적용 | 적용 |
| 그 외 | 활, 쇠뇌, 방패, 겉날개, 낚싯대, 늑대 갑옷 등 | 적용 | 미적용 | 미적용 | 미적용 |

- 도끼는 굴착 도구로 봅니다. 기준표대로 도끼 공격력은 등급으로 바뀌지 않습니다.
- 검은 거미줄과 대나무용 채굴 규칙을 갖고 있지만 굴착 도구가 아니므로 채굴 속도를 바꾸지 않습니다.
- 늑대 갑옷은 몸통 방어구라 방어구 4부위에 들지 않습니다. 기준표대로 내구도만 바뀝니다.
- 삼지창, 철퇴, 백금 주입 손도끼는 근접 무기로 처리해 공격력에 배율이 걸립니다.

### 수치 계산

- **내구도** 기본 최대 내구도에 배율을 곱하고 반올림합니다. 최소 1을 보장하며, 이미 닳은 장비는 새 최대치를 넘지 않도록 맞춥니다. 백분율 정수로 계산하므로 기준표와 항상 같은 값이 나옵니다.
- **공격력** 플레이어 기본 공격력 1을 포함한 값에 배율을 적용합니다. 기준표의 공격력 수치와 같은 기준입니다.
- **방어도** 부위별 방어도에 배율을 적용합니다. 방어 강도와 넉백 저항은 바꾸지 않습니다.
- **채굴 속도** 도구가 적합한 블록을 캘 때의 속도에만 배율을 적용합니다. 규칙에 없는 블록의 기본 속도는 맨손 기준값이므로 그대로 둡니다.
- 공격 속도, 채굴 가능 등급, 마법부여 효율, 기존 특수 효과는 등급으로 바뀌지 않습니다.

### 강화와의 관계

- 강화 +10강으로 오르는 공격력과 최대 체력, 채굴 효율은 등급 배율의 대상이 아닙니다. 등급은 아이템 기본 수치에만 적용합니다.
- 5티어 서리빛 검 +10강의 공격력은 8.8에 강화분 10을 더한 값입니다.
- 수치는 언제나 아이템 기본값에서 다시 계산하므로 등급과 강화를 여러 번 적용해도 값이 누적되지 않습니다.

### 표시

- 툴팁의 아이템 이름 바로 아래, 능력치 줄보다 위에 `B티어`를 빨간 글씨로 표시합니다.
- 아이템 이름 자체는 바꾸지 않습니다. 강화 단계 표시는 기존처럼 이름 뒤에 붙습니다.

## 도구 LV 1~100

S~F 등급과 +1~+10 강화에 더해, 도구 한 개마다 별도의 누적 EXP를 저장합니다. 기존 도구는 LV 1, EXP 0으로 시작합니다. 신규 데이터는 플레이어 인벤토리에서 1초에 한 번 준비하며, 도구를 실제 사용하는 경로에서도 준비합니다.

| 대상 | EXP를 받는 직접 행동 | LV당 채굴 속도 | LV당 최대 내구도 | LV 100 보너스 |
|---|---|---|---|---|
| 곡괭이 | 적합한 채굴 도구로 자연 블록 파괴 | +0.1% | +0.1% | 각각 +9.9% |
| 삽 | 적합한 채굴 도구로 자연 블록 파괴 | +0.1% | +0.1% | 각각 +9.9% |
| 도끼 | 적합한 채굴 도구로 자연 블록 파괴 | +0.1% | +0.1% | 각각 +9.9% |
| 괭이 | 성숙한 작물을 직접 파괴하여 수확 | +0.1% | +0.1% | 각각 +9.9% |
| 낚싯대 | 실제 전리품이 생성된 낚시 회수 | 없음 | +20% ÷ 99 | 내구도 +20% |

- 성공한 직접 행동마다 도구 EXP +1, 레벨마다 100 EXP가 필요합니다. LV 100까지 총 9,900 EXP이며 이후에는 추가 EXP를 쌓지 않습니다. 직업 EXP와 코인은 변경하지 않습니다.
- 곡괭이·삽·도끼·괭이 태그와 `FishingRodItem` 계열 중 기본 내구도가 있는 아이템만 포함합니다. 검·창·철퇴·삼지창·활·쇠뇌·방어구·가위·방패·겉날개 등은 제외합니다. 도끼의 공격력과 공격 속도는 LV로 올리지 않습니다.
- 괭이는 `CropBlock`의 최대 성장 단계, 다 자란 네더 사마귀와 코코아에 EXP를 받습니다. 어린 작물, 경작 반복, 범위 수확의 추가 블록에는 지급하지 않습니다. 우클릭 수확과 별도 모드의 수확 API는 이 직접 파괴 경로에 포함되지 않습니다.
- 곡괭이·삽·도끼는 해당 채굴 블록 태그에 맞아야 하며, 올바른 도구 등급을 요구하는 블록은 드롭 조건도 만족해야 합니다. 범위 채굴과 벌목의 추가 블록, 크리에이티브·관전자, 취소된 파괴에는 EXP를 지급하지 않습니다.
- 설치한 채굴 블록 좌표는 차원별 월드 데이터에 저장합니다. 설치 후 파괴 반복을 제외하며 피스톤 이동과 낙하 착지도 자연 블록으로 인정하지 않습니다. 도입 전 설치 이력과 명령어·다른 모드가 직접 생성한 블록의 출처는 알 수 없으므로 완전한 자연 생성 판정은 아닙니다.
- 낚시는 한 번에 추가 전리품이 여러 개 나와도 EXP +1입니다. 빈 회수, 엔티티 당기기, 전리품 생성 실패에는 지급하지 않습니다. 입질 시간·미끼 효과·직업 낚시 속도·드롭은 변경하지 않습니다.
- 채굴 속도는 `재질 기본 속도 × 등급 배율 × LV 배율`로 다시 계산합니다. 강화의 채굴 효율 수정자와 인챈트는 기존 계산 순서를 유지하고, 그 보너스 자체에 LV 배율을 곱하지 않습니다.
- 내구도는 `등급 적용 최대 내구도 × LV 배율`을 정수로 반올림합니다. 따라서 낮은 내구도의 도구는 일부 레벨에서 실제 최대치가 같을 수 있습니다. 낚싯대의 +20%는 반올림 전 배율 기준입니다.
- 최대 내구도가 변하면 기존 소모 비율을 유지합니다. 소모 내구도의 소수 부분은 올림해 LV 상승만으로 무료 수리를 받지 않도록 합니다. 일반 수리와 수선 인챈트는 기존 수리 동작을 유지합니다.
- 모루는 첫 번째 도구의 커스텀 데이터를 그대로 복사하는 바닐라 경로를 사용합니다. 제작 수리·숫돌은 첫 번째 도구, 대장장이 업그레이드는 기본 도구의 LV·EXP·등급·강화 기록을 계승합니다. 보조 도구 EXP를 합산하지 않으며 파손된 도구의 성장은 사라집니다.
- 클라이언트에도 모듈을 설치하면 `B티어 · LV 37 · EXP 42/100`, 실제 채굴 속도·최대 내구도와 LV 보너스를 표시합니다. 최대 레벨에는 `EXP MAX`를 표시합니다. 강화 단계는 기존 아이템 이름의 표시를 유지합니다.
- 등급 부여 설정을 꺼도 도구 LV는 동작합니다. 이미 기록된 등급은 기존 정책에 따라 유지합니다.

### 사용자 실행 확인 항목

이 변경에서 빌드·게임 실행·디버깅은 수행하지 않았습니다. 실행 시 다음 경계를 확인합니다.

- EXP 99→100에서 LV 1→2, EXP 9,899→9,900에서 LV 99→100, 이후 EXP 증가 중단.
- 같은 도구에 수치를 재적용해도 속도·내구도 배율이 누적되지 않는지와 최대치 변경 전후 남은 내구도 비율.
- 설치/파괴 반복, 재접속·재시작, 피스톤·낙하 이동, 보호 구역 파괴 취소에서 EXP 차단.
- 직접 채굴 1개와 3×3 채굴·벌목 추가 블록을 구분하고, 성숙 작물 수확만 괭이 EXP를 받는지.
- 주손·보조손 낚싯대의 정상 낚시 +1, 추가 전리품에서도 +1, 빈 회수와 엔티티 당기기에서 +0.
- 모루·제작 수리·숫돌·재질 업그레이드·수선에서 주 도구 LV·EXP와 강화 효과 유지, 보조 도구 EXP 미합산.
- 검·방어구·가위 등의 제외 대상과 도끼 공격력에 LV 효과가 붙지 않는지.

## 설정과 명령어

서버 시작 시 `config/serverutilities.properties`를 생성합니다. 수정 후 관리자 또는 서버 콘솔에서 다음 명령을 실행합니다. 콘솔에서는 앞의 `/`를 생략합니다.

```text
/serverutilities status
/serverutilities reload
```

`balance.creeper.multiplier`(일괄 4/3배 피해 보정)는 크리퍼 레벨로 대체되어 제거했습니다. 이전 설정 파일에 이 줄이 남아 있으면 알 수 없는 설정으로 기동이 멈추므로 지웁니다.

`status`는 설정과 실제 수면 비율을 표시하고, `reload`는 설정을 검증한 뒤 다시 적용합니다. 이벤트를 재등록하지 않습니다. 알 수 없는 키·잘못된 불리언·범위를 벗어난 숫자는 오류로 처리하며 설정 파일을 기본값으로 덮어쓰지 않습니다. 기동 중 오류는 로그에 기록하고 기동을 중단합니다. reload 오류 시 새 설정 객체를 활성화하지 않습니다.

| 키 | 기본값 | 허용값 | 동작 |
|---|---|---|---|
| `sleep.enabled` | `true` | `true` / `false` | 한 명이 정상적으로 잠들면 밤을 넘기도록 수면 비율을 0으로 설정 |
| `combat.elytra.enabled` | `true` | `true` / `false` | 습격 중 또는 위더 근처에서 활강 시 즉사 |
| `combat.golems.enabled` | `true` | `true` / `false` | 같은 전투 조건에서 주변 철골렘 제거 |
| `combat.range` | `80.0` | 1~128 | 위더 탐색·철골렘 제거 범위. 플레이어 경계 상자를 각 축으로 확장하는 AABB |
| `balance.creeper.enabled` | `true` | `true` / `false` | 크리퍼 레벨 배율을 폭발 피해와 블록 파괴 범위에 적용. 끄면 두 값 모두 바닐라 |
| `balance.hunger.enabled` | `true` | `true` / `false` | 행동으로 발생하는 피로도 보정 |
| `balance.hunger.multiplier` | `1.5` | 0~100, 유한수 | 행동 피로도 배율. 자연 회복이 직접 추가하는 피로도에는 미적용 |
| `balance.armor.enabled` | `true` | `true` / `false` | 방어도 소수점 사용과 유효 방어도 20 초과 구간의 피해 감소 곡선 |
| `balance.tier.enabled` | `true` | `true` / `false` | 내구도가 있는 장비에 S~F 등급을 추첨해 수치 적용 |
| `death.penalty.enabled` | `true` | `true` / `false` | 보존권 보호가 없으면 사망 시 무작위로 서로 다른 최대 2슬롯의 스택 전체 삭제 |
| `death.protection.enabled` | `true` | `true` / `false` | 사망 시 보존권 1개를 소비하고 인벤토리 보호 |
| `death.chest.enabled` | `true` | `true` / `false` | 손실 처리 뒤 남은 소지품을 사망 지점의 유품 상자에 보관 |
| `death.chest.expire_seconds` | `300` | 1~86400, 정수 | 설치 후 이 시간이 지나면 상자와 남은 내용물을 함께 삭제 |
| `death.chest.empty_seconds` | `3` | 0~3600, 정수 | 내용물을 모두 회수한 뒤 상자를 거두기까지의 시간 |
| `spawn.scatter.enabled` | `true` | `true` / `false` | 신규 접속자를 기준 좌표 주변 무작위 지점에 배치하고 개인 리스폰 지점으로 고정 |
| `spawn.scatter.radius` | `3000` | 1~1000000, 정수 | 기준 좌표에서 X·Z 각각 이 거리 안에서 무작위 좌표를 뽑음 |
| `starter.kit.enabled` | `true` | `true` / `false` | 최초 접속 때 시작 장비 지급 |

기존 전투 규칙의 크리에이티브·관전자 예외 정책은 바꾸지 않았습니다. 사망 손실·보존권 소비는 기존처럼 크리에이티브·관전자를 제외합니다. 사망 손실과 보존권은 각각 켜고 끌 수 있고, 두 설정 모두 끄면 신규 사망에 대해 이 모듈이 아이템을 변경하지 않습니다. 이미 성립한 보호 상태는 설정을 꺼도 리스폰까지 복원합니다.

`keep_inventory`가 켜져 있어도 사망 손실·보존권 소비는 기존처럼 별도로 적용됩니다. 손실이 꺼져 있고 보존권도 없으면 아이템 유지 여부는 바닐라 게임 규칙을 따릅니다. 유품 상자는 `keep_inventory`가 켜져 있으면 만들지 않습니다.

## 유품 상자

보존권이 없는 사망에서 손실 2슬롯을 먼저 지운 뒤, 남은 소지품을 사망 지점에 놓인 `serverutilities:death_chest` 블록에 담습니다. 바닐라 상자와 같은 모양의 별도 블록이며 아이템 형태는 없습니다.

- 기본 인벤토리·장비·보조 손·배낭 칸을 무작위 순서로 순회해 27칸까지 담습니다. 넘치는 스택은 인벤토리에 남겨 바닐라 사망 드롭이 그대로 바닥에 떨어뜨립니다. 소실 저주 아이템은 상자에 넣지 않고 바닐라대로 소멸합니다. 경험치 드롭은 바뀌지 않습니다.
- 사망 좌표가 기본 설치 위치이며 공중이어도 그대로 놓습니다. 공기·물·용암·잔디처럼 교체 가능한 블록만 빈 칸으로 봅니다. 막혀 있으면 수평 4방향, 위, 아래 순으로 찾고, 전부 막혀 있으면 사망 좌표의 블록을 강제로 덮어씁니다. 그 칸이 다른 유품 상자이면 위·아래로 물러나 다른 블록을 덮어씁니다. 공허 사망은 월드 최소 높이로 올립니다.
- 사망한 플레이어에게 좌표와 만료 시간을 채팅으로 알립니다. 넘친 스택 수도 함께 알립니다. 상자 이름은 `OOO님의 유품 상자`입니다.
- 모든 플레이어가 열 수 있고 넣기·꺼내기·호퍼 추출에 제한이 없습니다. 위가 막히면 바닐라 상자처럼 열리지 않으므로 사용자가 직접 뚫어야 합니다.
- 회수·만료 전에는 파괴되지 않습니다. 파괴 시간 -1과 기반암 수준의 폭발 저항을 가지며 위더·드래곤 면역 태그에 들어갑니다. 최종 방어선으로 `Level.setBlock`에서 유품 상자를 다른 블록으로 바꾸는 모든 요청을 거부하므로 크리에이티브 채굴·명령어·다른 모드의 교체도 막힙니다. 옆에 상자를 놓아도 합쳐지지 않습니다.
- 설치 시각을 실제 시각으로 블록 엔티티에 저장합니다. 청크가 언로드되거나 서버가 꺼져 있어도 시간은 계속 흐르고, 만료된 상자는 청크가 다시 로드된 첫 틱에 사라집니다. 만료 시 남은 내용물은 바닥에 떨어지지 않고 삭제됩니다.
- 내용물이 모두 비면 `death.chest.empty_seconds` 뒤 상자를 거둡니다. 그 사이 다시 넣으면 타이머를 초기화합니다. 거둘 때 상자를 보고 있는 플레이어의 창을 닫고, 물속이었으면 물을 되돌립니다.
- 클라이언트는 이 모듈이 있어야 상자를 볼 수 있습니다. 미설치 클라이언트에는 파티클 텍스처만 있는 빈 모델로 보입니다.

## 수면 규칙 보존·복원

26.2의 `ServerLevel.getGameRules()`는 서버의 공유 규칙을 사용합니다. 처음 활성화할 때 해당 월드 루트의 `serverutilities-sleep.properties`에 이전 `players_sleeping_percentage` 값을 기록하고, 실제 값을 0으로 바꿉니다. 재시작·reload 시 최초 값을 덮어쓰지 않습니다.

`sleep.enabled=false`로 바꾼 뒤 reload하면 현재 값이 관리 값인 0일 때 원래 값을 복원합니다. 관리자가 별도로 다른 숫자를 설정했다면 그 값을 유지합니다. 복원이 끝나면 관리 기록을 제거합니다. 활성화 상태에서 reload하면 수면 비율은 다시 0으로 적용됩니다.

복원 기록이 손상되면 그대로 보존하고 적용을 중단합니다. 기록 저장 실패 시 게임 규칙을 바꾸지 않습니다. 비활성화 과정에서 기록 삭제가 실패하면 규칙은 이미 복원되었을 수 있으므로 `status`와 로그를 확인하고 다시 reload합니다.

이 기능은 바닐라 수면 조건을 따릅니다. 잠자는 사람이 없거나 잠을 잘 수 없는 상황을 무시하고 강제로 아침으로 만들지 않습니다. 시간 진행·날씨 게임 규칙은 변경하지 않습니다.

## 사망 데이터 호환

- 보존권 ID는 `advancednetherite:death_item_protection_scroll`입니다. 아이템 등록·레시피·텍스처는 Advanced Netherite에 유지했습니다.
- 보호 상태는 이전과 같은 플레이어 저장 키 `JobsPlusDeathItemProtected`를 읽고 씁니다.
- 실제 사망 문구가 만들어지기 전에 손실·보호를 한 번 처리하고, 남은 소지품은 아이템 드롭 직전에 유품 상자로 옮깁니다. 보호된 인벤토리는 드롭을 취소하고 `restoreFrom`에서 복원합니다.
- 사망 손실은 기본 인벤토리·장비·보조 손·배낭 추가 칸의 비어 있지 않은 슬롯에서 중복 없이 최대 2개를 뽑습니다. 기존처럼 낱개 수량이 아닌 슬롯의 스택 전체를 삭제하며, 1슬롯만 있으면 1슬롯만 삭제합니다. 삭제한 아이템은 기존 사망 원인 뒤에 붙여 한 메시지로 공지하고, 소지품이 없어 삭제한 아이템이 없으면 붙이지 않습니다.
- Advanced Netherite의 배낭 연동은 장착 가방이 선택되었을 때 내부 아이템도 드롭 없이 모두 삭제합니다. 함께 비워진 내부 칸은 손실 횟수로 세지 않고 남은 슬롯에서 다시 선택합니다. 여분 가방 삭제는 장착 가방에 영향을 주지 않습니다. 이 동작을 적용하려면 수정된 Advanced Netherite도 함께 교체해야 합니다.
- 사망 화면에서 접속을 끊거나 서버를 재시작하는 경우를 위해 보호 상태를 저장합니다.
- 유품 상자 담기는 `DeathChests.store`에서 처리합니다. Advanced Netherite의 배낭 삭제 연동이 `DeathRules.beforeDrops` 안의 `removeItemNoUpdate` 호출을 Redirect로 잡으므로, 손실 루프는 그 메서드에 그대로 두고 상자 담기는 별도 클래스에서 호출합니다.
- 사망·전투 공지는 서버가 완성한 한글 문장으로 보냅니다. 신규 모듈의 클라이언트 언어 파일이 필요하지 않습니다.
- 기존 직업·코인·주식·추가 직업 슬롯 데이터는 Jobs+가 계속 처리합니다.

## 몬스터 생성 장비

- 오버월드에서 좀비 계열과 스켈레톤 계열 몬스터가 새로 생성될 때, 개체별로 방어구와 무기를 각각 30% 확률로 따로 추첨합니다. 두 추첨은 서로 영향을 주지 않으므로 방어구만 21%, 무기만 21%, 둘 다 9%, 둘 다 없음 49%입니다. 정해진 마릿수마다 강제 배정하는 방식은 아닙니다.
- 피글린과 피글린 야수는 차원과 관계없이 방어구만 30% 확률로 추첨합니다. 석궁 사격·금 도끼·금 물물교환이 고유 행동이라 무기는 바꾸지 않고, 던져 준 금을 주워야 물물교환이 되므로 줍기도 막지 않습니다. 네더에서만 사는 몬스터라 오버월드 조건을 두지 않습니다.
- 조건에 맞지 않는 개체(오버월드 밖의 좀비·스켈레톤 계열, 그 밖의 몬스터)도 추첨을 끝낸 것으로 기록합니다. 그래서 네더에서 태어난 좀비 피글린이나 위더 스켈레톤이 나중에 오버월드로 넘어와도 장비를 받지 않습니다.
- 방어구에 당첨되면 가죽·구리·금·사슬·철·다이아몬드·네더라이트 중 한 재질의 4부위 풀세트를 지급합니다. 재질 7종은 같은 확률입니다. 당첨되지 않은 쪽은 원래 몬스터의 기본 장비를 사용합니다. 지급 방어구에는 장비 등급(S~F)을 붙이지 않으므로 원래 수치 그대로입니다.
- 무기는 위 5재질의 검·도끼·창 15종 중에서 고릅니다. 수정된 TACZ와 함께 설치하면 로드된 총기도 같은 후보군에 들어갑니다. 후보 아이템/총기 ID 각각의 확률은 동일합니다.
- 지급한 방어구·양손 장비의 드롭 확률은 0이며, 줍기로 장비를 교체하지 못하게 합니다. 사망 직전에도 드롭 확률 0을 적용하므로 약탈 인챈트로 지급 장비를 얻을 수 없습니다. 몬스터의 일반 전리품은 원래 규칙을 따릅니다.
- 추첨 완료·생성 대기·지급 여부를 몬스터 저장 데이터에 기록합니다. 일반 청크 재로드·재접속·차원 이동에서 다시 추첨하지 않으며, 기존 저장 몬스터를 일괄 재장비하지 않습니다.
- 소환 명령·스폰 알·스포너·분열 개체도 신규 생성 경로에서 처리합니다. 월드 생성 중 먼저 저장된 새 개체는 생성 대기 표시를 읽어 최초 로드 시 지급합니다.
- 몬스터의 총기는 추가 장착 파츠 없이 탄창이 가득 찬 채로 생성되며 탄약 아이템 없이 발사합니다. 쏠 때마다 탄창이 줄고, 다 쓰면 재장전 시간만큼 사격을 멈춘 뒤 탄창을 가득 채웁니다. 재장전 횟수에는 제한이 없습니다. 대상 쪽으로 고개를 돌린 뒤에만 쏩니다. 서버의 총기 발사·쿨타임·볼트·재장전·과열 처리는 TACZ가 담당합니다. 이 기능을 적용하려면 수정된 Server Utilities와 TACZ를 함께 교체해야 합니다.

생성/로드 구분은 프로젝트에 고정된 [Fabric API 0.154.2+26.2의 `ALLOW_LOAD` 이벤트](https://github.com/FabricMC/fabric-api/blob/0.154.2%2B26.2/fabric-lifecycle-events-v1/src/main/java/net/fabricmc/fabric/api/event/lifecycle/v1/ServerEntityEvents.java)를 사용합니다.

## 몬스터 레벨 표시

장비 추첨 대상 몬스터(오버월드의 좀비·스켈레톤 계열, 피글린·피글린 야수)와 크리퍼의 머리 위에 `LV1`~`LV7`을 표시합니다. 장비 추첨 대상의 레벨은 방어구 점수와 무기 점수의 평균을 반올림한 값이며, .5는 올립니다. 크리퍼는 아래 [크리퍼 레벨](#크리퍼-레벨)을 따릅니다.

| 등급 | 점수 | 방어구 세트 | 4부위 방어도 합 | 부위당 방어 강도 |
|---|---:|---|---:|---:|
| F | 1 | 가죽 | 7 | 0 |
| E | 2 | 구리 | 10 | 0 |
| D | 3 | 금 | 11 | 0 |
| C | 4 | 사슬 | 12 | 0 |
| B | 5 | 철 | 15 | 0 |
| A | 6 | 다이아몬드 | 20 | 2 |
| S | 7 | 네더라이트 | 20 | 3 |

- 방어구 점수는 위 표를 따릅니다. 방어도 합이 같은 다이아몬드와 네더라이트는 방어 강도로 나눴습니다.
- 무기 점수는 총기면 TACZ 총기 등급(F=1 ~ S=7), 검·도끼·창이면 2점입니다. 총기 등급은 TACZ의 `src/main/resources/tacz/gun_grades.json`을 읽으며, 이 파일은 `tools/apply_tier_colors.py`가 이름 색과 같은 표에서 만듭니다. 등급표에 없는 총기는 F로 계산하고 서버 로그에 한 번 경고합니다.
- 지급받지 못한 쪽은 1점으로 계산합니다. 예를 들어 네더라이트만 입은 개체는 LV4, 장비가 없는 개체는 LV1입니다.
- 추첨으로 지급한 장비만 계산합니다. 스켈레톤의 활, 드라운드의 삼지창, 피글린의 금 검·석궁처럼 원래 가진 장비는 지급받지 못한 것과 같게 봅니다.
- 레벨은 추첨 때 한 번 정해 몬스터 저장 데이터(`ServerUtilitiesMonsterLevel`)에 기록합니다. 이 기능 이전에 추첨을 마친 개체는 처음 로드될 때 지급 기록과 현재 장비로 계산합니다.
- 서버는 플레이어가 몬스터를 추적하기 시작할 때 레벨을 한 번 보냅니다. 클라이언트는 바닐라 이름표와 같은 위치·크기로 그리고, 이름표나 점수 줄이 있으면 그 위 줄에 놓습니다.
- 벽에 가려지면 보이지 않고, 32블록보다 멀거나 투명화 상태이거나 F1로 화면 표시를 끄면 그리지 않습니다.
- 글자 색은 총기 이름 색과 같습니다. LV1~LV7이 차례로 F~S 등급 색입니다: 연두 `§a`, 하늘 `§b`, 파랑 `§9`, 보라 `§5`, 노랑 `§e`, 빨강 `§c`, 주황 `§6`.
- 클라이언트에도 이 모듈이 있어야 보입니다. 미설치 클라이언트에는 보내지 않습니다.

| 방어구 \ 총기 | F | E | D | C | B | A | S |
|---|---:|---:|---:|---:|---:|---:|---:|
| 없음 | 1 | 2 | 2 | 3 | 3 | 4 | 4 |
| 가죽 (F) | 1 | 2 | 2 | 3 | 3 | 4 | 4 |
| 구리 (E) | 2 | 2 | 3 | 3 | 4 | 4 | 5 |
| 금 (D) | 2 | 3 | 3 | 4 | 4 | 5 | 5 |
| 사슬 (C) | 3 | 3 | 4 | 4 | 5 | 5 | 6 |
| 철 (B) | 3 | 4 | 4 | 5 | 5 | 6 | 6 |
| 다이아몬드 (A) | 4 | 4 | 5 | 5 | 6 | 6 | 7 |
| 네더라이트 (S) | 4 | 5 | 5 | 6 | 6 | 7 | 7 |

무기가 없으면 F 열, 근접 무기면 E 열과 같습니다.

### 크리퍼 레벨

크리퍼는 장비가 없으므로 새로 생성될 때 LV1~LV7을 같은 확률(각 1/7)로 뽑습니다. 차원과 생성 경로(자연 생성·스포너·스폰 알·소환 명령)에 관계없이 적용하며, 레벨이 폭발 배율을 정합니다.

| 레벨 | LV1 | LV2 | LV3 | LV4 | LV5 | LV6 | LV7 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 배율 | 1.0 | 1.3 | 1.6 | 1.9 | 2.2 | 2.5 | 2.8 |

- 폭발 피해: 바닐라가 같은 자리에서 주는 피해에 배율을 곱합니다. 예전의 일괄 4/3배 보정을 대체하므로 LV1은 바닐라 피해 그대로입니다. 플레이어는 난이도 보정을 받은 피해에 배율을 곱합니다.
- 블록 파괴 범위: 폭발이 블록을 부수는 광선의 세기에 배율을 곱합니다. `mobGriefing`이 꺼져 있으면 블록을 부수지 않는 것은 바닐라와 같습니다.
- 피해가 닿는 거리와 넉백은 바닐라 그대로입니다. 충전된 크리퍼는 바닐라의 2배 반경 위에 레벨 배율이 곱해집니다.
- `balance.creeper.enabled=false`면 두 배율 모두 바닐라로 돌아갑니다. 레벨 추첨과 머리 위 표시는 그대로입니다.
- 레벨은 장비 몬스터와 같은 저장 키(`ServerUtilitiesMonsterLevel`)에 기록하며 청크 재로드·재시작 후에도 유지합니다.

### 레벨별 경험치 구슬

레벨이 붙은 몬스터가 죽을 때 떨어뜨리는 경험치 구슬에 레벨 배율을 곱합니다. 결과는 반올림하며 .5는 올립니다.

| 레벨 | LV1 | LV2 | LV3 | LV4 | LV5 | LV6 | LV7 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 배율 | 1.0 | 1.3 | 1.6 | 1.9 | 2.2 | 2.5 | 2.8 |

- 장비 추첨 대상(오버월드 좀비·스켈레톤 계열, 피글린·피글린 야수)과 크리퍼에 적용합니다. 레벨이 없는 몬스터는 바닐라 그대로입니다.
- 바닐라가 장비 1개당 더하는 경험치(1~3)를 포함한 값에 곱합니다.
- 사냥꾼 영혼 수확의 추가 구슬은 배율을 곱하지 않은 원래 경험치를 기준으로 계산합니다.
- 플레이어가 공격한 몬스터가 불·독처럼 공격자 없는 피해로 죽으면, 바닐라는 마지막 공격 후 5초 안에 죽어야 구슬을 떨어뜨립니다. 이 모듈은 20초까지 인정해 직업 처치 보상과 기준을 맞춥니다. 다른 생물이 죽인 경우는 바닐라 그대로입니다.

## 보스 소환수

오버월드의 워든·위더가 플레이어를 공격 대상으로 잡으면 보스 주변에 좀비·스켈레톤을 소환합니다.

- 대상을 잡은 즉시 한 번, 이후 30초마다 보스별로 좀비 5마리·스켈레톤 5마리가 되도록 모자란 수만 채웁니다. 예를 들어 좀비 3마리가 죽었으면 좀비 3마리만 다시 소환합니다.
- 보스가 대상을 잠깐 놓쳤다가 다시 잡아도 30초 간격은 그대로입니다. 크리에이티브·관전자는 대상으로 보지 않습니다.
- 보스 중심에서 10블록 안의, 발밑이 단단하고 몸이 들어갈 빈 땅에 소환합니다. 물·용암 안과 월드보더 밖에는 소환하지 않으며, 자리를 찾지 못한 몹은 다음 보충 때 다시 채웁니다.
- 좀비는 아기·닭 기수 없이 어른으로만 소환하고, 소환 즉시 보스의 대상 플레이어를 노립니다.
- 소환한 몹도 자연 생성 몹과 같은 장비 추첨(방어구·무기 각 30%)과 레벨 계산을 거칩니다. 직업 메트릭에는 스폰 원인 `mob_summoned`로 기록됩니다.
- 소환한 몹은 `serverutilities.boss_minion.<보스 UUID>` 태그로 구분하므로 서버를 다시 시작해도 남은 수를 그대로 셉니다.
- 보스가 죽거나 사라져도 소환한 몹은 남습니다. 아군 피해와 햇빛에 타는 것은 바닐라 그대로입니다.
- 네더·엔드의 위더는 소환하지 않습니다.

### 갇힌 위더 탈출

오버월드의 위더가 플레이어를 노리는 동안 10초 넘게 2블록도 움직이지 못했고, 그 사이 블록에 부딪혔거나 대상과 수평으로 8블록 넘게 떨어져 있으면 갇힌 것으로 보고 가장 가까운 플레이어 뒤로 옮깁니다.

- 64블록 안의 생존·모험 모드 플레이어 중 가장 가까운 플레이어를 고릅니다. 등 뒤 3·4·2블록 순서로, 높이를 0·1·2블록 올려 가며 위더 몸이 들어가는 빈자리를 찾습니다. 빈자리가 없으면 다음 검사 때 다시 시도합니다.
- 자유롭게 싸우는 위더는 대상 가까이 다가가 맴돌므로 이 조건에 걸리지 않습니다.

## 시작 위치 분산

최초 접속자가 선 자리를 기준 좌표로 월드 폴더의 `serverutilities-spawn.properties`에 저장하고, 이후 신규 접속자는 기준 좌표에서 X·Z를 각각 `±spawn.scatter.radius`(기본 3000) 안에서 균등하게 뽑은 지점에 배치합니다. Y는 뽑지 않고 바닐라 탐색이 지면 높이로 정합니다.

- 뽑은 좌표를 바닐라 `PlayerSpawnFinder`에 넘겨 주변 `spawnRadius`(기본 10) 안의 안전한 지면을 찾습니다. 청크 생성은 서버 스레드를 붙잡지 않고, 그동안 플레이어를 무적·이동 잠금 상태로 둡니다.
- 바닐라는 주변에 땅이 없으면(바다·큰 호수 한가운데) 뽑은 좌표에서 높이만 맞춘 수면 바로 위 좌표를 돌려줍니다. 그래서 결과 좌표의 발밑 한 칸이 물·용암이 섞이지 않고 윗면이 단단한 블록인지 다시 확인하고, 아니면 새 좌표를 뽑습니다. 최대 20회까지 다시 뽑고, 모두 실패하면 옮기지 않고 다음 접속 때 다시 시도합니다.
- 정해진 자리를 개인 리스폰 지점(강제 리스폰)으로 저장하고 좌표를 채팅에 빨간 글씨로 알립니다. 침대로 리스폰 지점을 정하면 침대가 우선입니다.
- 침대가 없어졌거나 개인 리스폰 지점이 막혔으면 개인 좌표에서 다시 시작합니다. 개인 좌표가 막혔으면 주변 2청크 안에서 발밑에 블록이 있는 빈 자리를 찾고, 없으면 새 좌표를 배정합니다.
- 발밑 검사는 새로 배정하는 자리에만 적용합니다. 이미 저장된 개인 좌표는 다시 검사하지 않으므로, 이전 버전에서 수면 위를 배정받은 플레이어는 그 자리를 그대로 씁니다.
- 월드보더 안으로 좌표를 자르지 않습니다. 월드보더를 기준 좌표에서 반경보다 좁게 두면 경계 밖이 뽑힐 수 있습니다.

## 시작 장비

최초 접속 때 한 번 시작 장비를 지급합니다. 사망 후 새 플레이어 개체로 바뀌어도 지급 기록을 옮기므로 다시 받지 않습니다. `starter.kit.enabled`(기본값 `true`)로 끌 수 있습니다.

| 구분 | 아이템 | 지급 방식 |
|---|---|---|
| 방어구 | 금 투구·흉갑·레깅스·부츠 | 바로 착용. 해당 칸이 차 있으면 인벤토리 |
| 방패·도구·무기 | 방패, 금 곡괭이·도끼·삽·괭이·검 | 인벤토리 |
| 총기 | 등록된 권총(`type`이 `pistol`, 기본 총기팩 15종) 중 무작위 1정 | 인벤토리. 권총마다 같은 확률이며, 작업대 제작품처럼 빈 탄창으로 지급 |
| 탄약 | 그 총의 탄약 3탄창 분량(기본 장탄수의 3배) | 인벤토리. 탄약 한 묶음의 최대 개수를 넘으면 나눠서 지급 |
| 테스트 서버 펫 | 전설 펫 상자(`advancednetherite:legend_petbox`) 1개 | 인벤토리. Advanced Netherite가 설치된 경우 지급 |

- 인벤토리가 가득 차면 발밑에 떨어뜨립니다.
- 전설 펫 상자도 최초 스타터팩 지급에 포함되며, 이미 스타터팩을 받은 플레이어에게는 소급 지급하지 않습니다.
- 총기와 탄약은 수정된 TACZ가 함께 설치된 경우에만 지급합니다. 확장 탄창 같은 부착물이 없는 기본 장탄수 기준입니다. 등록된 권총이 없으면 총기 없이 나머지 장비만 지급합니다.
- 지급 후 채팅으로 장비 목록과 받은 총기 이름·탄약 수를 알립니다.

## 거래 횟수 제한 해제

주민과 떠돌이 상인의 거래를 횟수 제한 없이 계속할 수 있습니다. 설정으로 끄지 않는 고정 규칙입니다.

바닐라는 거래할 때마다 해당 거래의 사용 횟수를 올리고, 최대 횟수에 닿으면 품절로 막습니다. 26.2 기본 거래 데이터의 최대 횟수는 대부분 12회 또는 16회이고 일부는 1~8회입니다. 주민은 직업 블록에서 하루 최대 2회만 재입고하며, 재입고 때 쌓인 사용 횟수만큼 수요를 올려 가격을 인상합니다. 떠돌이 상인은 재입고하지 않습니다.

- 거래해도 사용 횟수가 늘지 않습니다. 품절과 재입고 대기가 생기지 않고, 수요에 따른 가격 인상도 멈춥니다.
- 적용 전에 이미 품절된 거래도 재입고를 기다리지 않고 바로 열립니다.
- 좀비 치료, 마을의 영웅, 평판에 따른 가격 변동은 그대로 적용됩니다. 주민 경험치와 레벨업, 신규 거래 해금도 기존처럼 거래마다 진행됩니다.
- 적용 전 수요로 이미 오른 가격은 주민이 직업 블록에서 일하는 날마다 바닐라 규칙대로 수요가 줄어 기본 가격으로 돌아옵니다.
- `MerchantOffer`의 사용 횟수 증가와 품절 판정 두 메서드만 바꿉니다. 대상 메서드가 없으면 Mixin 적용을 실패시켜 버전 변경으로 인한 오적용을 드러냅니다.
- 서버만 설치해도 거래 제한은 풀립니다. 다만 미설치 클라이언트는 적용 전에 품절된 거래에 빨간 X가 보이고, 한 거래 창에서 최대 횟수를 넘겨 연속 거래하면 창을 다시 열 때까지 품절로 표시될 수 있습니다. 표시를 서버와 맞추려면 클라이언트에도 설치합니다.

## 빌드와 검증

Java 25 환경에서 모듈 폴더 안에서 실행합니다.

```powershell
.\gradlew.bat build
```

릴리스 파일은 `build/libs/ServerUtilities-26.2-1.0.1.jar`입니다. 자석석 설치·폭발·피스톤 이동과 Jobs+ 접속 호환성은 [운영 서버 업데이트 확인 항목](../ReadMe.md#운영-서버-업데이트)에 따라 실제 게임에서 별도로 검증합니다.

전체 빌드·수집은 `python Build_File-26.2/collect_fabric_jars.py`로 수행합니다. 대상은 11개이며, 빌드·검증·임시 복사가 성공한 후 결과를 교체합니다.

각 기능 추가와 기존 모드의 해당 구현 제거를 같은 커밋으로 관리합니다. 수면 기반 커밋 위에 전투, 밸런스, 사망 처리를 순서대로 적용하며 빌드 수집 연결과 수집 실패 복구는 별도 커밋으로 관리합니다. 전체 기능을 되돌릴 때는 의존하는 변경부터 역순으로 되돌립니다.

전체 이전 버전으로 되돌릴 때:

1. `sleep.enabled=false`로 수정하고 `/serverutilities reload` 및 `status`로 복원을 확인합니다.
2. 서버를 종료합니다.
3. Server Utilities JAR을 제거하고 대응하는 이전 Jobs+·Advanced Netherite JAR을 함께 복원합니다.
4. 이미 사망 화면에 있는 플레이어의 보존 상태가 있으면, 같은 저장 키를 지원하는 이전 Jobs+로 복원합니다.

JAR만 제거하면 수면 비율 0은 월드에 남을 수 있습니다. 미리 복원하지 못했다면 기록된 원래 숫자로 `/gamerule minecraft:players_sleeping_percentage <원래값>`을 적용합니다. 기능이 실행되어 이미 삭제된 아이템은 코드 롤백으로 복구되지 않습니다.

청크 보호 분리, 재파종 대기열 개선, 탐색 성능 최적화, 일반 버전 범위 파서 개선은 이번 구현에 포함하지 않았습니다.
