퀘스트형 업적 구현 안내

수정 범위
- Jobs+: 100종 정의, 시즌 저장, 서버 판정, 화면/패킷, 작업자 추적, 보상 수령, 주식 거래 원장.
- ArcLib: 추가 드롭 적용 전의 낚시 성공 이벤트, 사망 공로 재조회.
- 빌드 설정: Server Utilities를 Jobs+보다 먼저 빌드하고 컴파일/런타임 의존으로 등록.
- 기존 칭호 화면 및 작업 중인 다른 변경사항은 유지합니다.

버전과 확인 범위
- 기준은 저장소 26.3 브랜치입니다. 확인 당시 원격/로컬 HEAD: 6c0bd5def417bd1fc12a1059036c4533958c7220.
- 이 브랜치의 실제 모듈 폴더, Minecraft 의존성 및 전체 빌드 스크립트는 현재 26.2입니다.
- 이번 수정은 기존 빌드 대상과 API에 맞춰 작성했습니다. Minecraft 버전 이관은 별도 범위입니다.
- 실행·빌드·게임 디버깅·테스트 실행은 하지 않았습니다. 소스와 호출 관계, API 선언을 검토했습니다.
- 실행 중 오류가 없다는 보장은 아직 할 수 없으며 아래 실제 서버 검증이 필요합니다.
- commit, push 및 GitHub 원격 파일 수정은 하지 않았습니다.

사용 방법
1. Jobs+ 화면의 업적 탭 → 업적 목록을 엽니다.
2. 직업/생활/탐험/경제/장비/펫 분류와 항목을 선택합니다.
3. 개별 목표값, 선행 조건, 판정 대상 목록을 확인합니다.
4. 달성 후 '완료 · 보상 수령'을 눌러 일반 다이아몬드 아이템을 받습니다.
5. 인벤토리 36칸에 보상 전체가 들어갈 수 없으면 아무것도 지급하지 않고 수령 대기를 유지합니다.

적용한 판정
- 시즌별 누적값은 선행 업적의 해금 여부와 무관하게 저장합니다. 500 다음 2,000은 추가 1,500입니다.
- 목표 달성 기록과 수령 기록은 별도입니다. 선행 목표가 달성되면 다음 단계가 해금됩니다.
- 일반 스킬은 등록된 전체 구매 단계와 ACTIVE/INACTIVE 보유 기록을 대조합니다. 하이퍼는 제외합니다.
- 기존 직업(활성/비활성) 레벨·구매 스킬, 본인 소유 펫의 현 상태, 현재 청크 소유 상태는 인정합니다.
- 과거 누적 채굴·수확·BTC·이동·장비 EXP 등은 신뢰할 개인별 기록이 없으므로 소급 생성하지 않습니다.
- 장비는 사용자가 확정한 '본인이 EXP를 얻어 목표 레벨에 도달한 순간'을 기록합니다.
  예: Lv.99 장비를 빌려 Lv.100을 달성하면 100 목표만 기록하고, 25/50 목표를 소급하지 않습니다.
  장비 개체 UUID와 목표별 도달 기록을 저장하며, 총기는 모델/도구는 종류별로 구분합니다.
- 강화는 실제 성공으로 이전 단계보다 올라간 결과만 기록합니다.
- 채굴/굴착은 기존 영구 설치 블록 원장과 Arc 설치 기록을 확인한 뒤 실제 성공한 파괴만 기록합니다.
  설치 기록이 없던 과거 설치 블록, 외부 월드 편집이 별도 기록 없이 생성한 블록은 원천 구분할 수 없습니다.
- 수확은 성숙 블록 1개당 1회입니다. 농부 범위 수확은 성공한 주변 블록만 추가하고 드롭 배수는 제외합니다.
  지정 대상: 밀/당근/감자/비트/네더 사마귀/코코아/완전히 자란 달콤한 열매.
- 낚시는 기존 자동 낚시 판정 통과 후 원본 전리품 회수 1회만 인정합니다. 추가 드롭 전에 어종을 기록합니다.
- 양조는 본인이 병과 재료를 직접 투입한 경우, 효과 없는 병 → 효과 있는 병의 첫 완성 수량입니다.
  연장/강화/투척형 전환은 다시 세지 않습니다. 호퍼 투입은 작업자 미상으로 취급합니다.
  본인이 직접 투입한 상태를 유지하면 로그아웃 중 로드된 양조대의 완성도 본인 UUID에 기록합니다.
- 제련은 투입 작업자를 완제품 수량에 FIFO로 계승합니다. 본인이 직접 꺼낸 본인 결과물만 인정합니다.
  호퍼 투입/회수 및 다른 사람이 투입한 재료의 결과물은 제외합니다. 호퍼가 꺼낸 수량은 원장에서 차감합니다.
- 이동은 바닐라 서버 WALK_ONE_CM + SPRINT_ONE_CM, 비행은 AVIATE_ONE_CM 통계를 사용합니다.
- 일반 처치는 기존 Arc 공로 판정을 사용합니다. 적대몹 총계는 Enemy 분류를 적용합니다.
- 드래곤은 사용자가 확정한 최대 HP 5% 실제 피해 + 사망 연출 종료 시 같은 차원 128블록 이내 생존입니다.
  직접 피해의 실제 체력 감소와 마지막 일격을 기록하며, 드래곤 UUID별 1회 인정합니다.
  유효 기여자는 드래곤 업적과 적대몹 총계 모두에 1회를 받습니다.
- 습격 승리는 바닐라 heroesOfTheVillage에 등록되어 승리 당시 같은 차원에 생존한 플레이어에게 1회 인정합니다.
- 오버월드는 현재 서버 생성기의 가능한 바이옴 목록, 네더는 지정된 바닐라 5종을 사용합니다.
  구조물 방문은 실제 구조물 경계 안의 서버 위치를 사용하며 방문은 매 틱 위치 변화와 차원 변경에서 확인합니다.
  '모험의 시간'은 현재 서버의 바닐라 발전 과제 완료 상태와 실제 criteria 목록을 사용합니다.
  대상 바이옴/몹은 업적 상세 화면에서 확인할 수 있습니다.
- BTC는 직업 보상으로 실제 지급한 수량만 기록합니다. 이체/줍기/상자 회수/상점은 해당 BTC에 더하지 않습니다.
- 청크는 차원과 청크 좌표로 구분한 동시 본인 소유 수의 최고 기록입니다. 해제 후 다른 청크를 더해 누적하지 않습니다.
- 겉날개는 서버 상점의 등록된 500 BTC 구매, 납품은 성공한 실제 작물 판매 수량만 기록합니다.
- 주식은 시즌 이후 실제 체결 매수 원금 합계 1 BTC 이상 + 해당 투자 원금 전량 직접 매도를 요구합니다.
  기존 보유분은 FIFO로 제외하며 취소/실패/예약만으로는 인정하지 않습니다.
  원금 연산은 기존 계좌의 소수 8자리 기준을 사용합니다. 같은 종목은 시즌당 한 번만 인정합니다.
  강제 청산된 미완료 사이클은 제외하되 이전에 전량 매도를 끝낸 원금 합계는 유지합니다.
- 크리에이티브/관전자 행동은 집계와 수령에서 제외합니다.

시즌/저장
- Jobs+ 설정의 achievements.season 값으로 시즌을 구분합니다. 기본값은 season3입니다.
- 새 시즌에는 아직 사용하지 않은 ID로 바꾸고 서버를 재시작합니다. 같은 ID로 돌아가면 그 시즌의 기록을 사용합니다.
- 진행/달성 원장: <월드>/jobsplus-achievements.json, 백업 .bak.
- 수령 상태: 플레이어 NBT의 JobsPlusAchievementClaims, 키 형식 <시즌>/<업적 ID>.
- 보상은 진행 원장 저장 성공 후 인벤토리와 수령 키를 같은 플레이어 파일에 함께 저장합니다.
  플레이어 저장 실패 시 인벤토리/수령 키를 복원합니다. 연속 요청은 서버에서 제한하며 기수령 키도 다시 확인합니다.
- 작업자 원장은 해당 화로/양조대 블록 엔티티 NBT에 저장합니다.
- 진행 원장은 1,200 서버 틱마다, 로그아웃, 서버 종료, 보상 수령, 드래곤/습격 인정 시 저장합니다.
  비정상 종료로 저장 전 누적값이 유실될 수 있습니다. 1,200틱은 정상 20 TPS에서 약 60초입니다.
- 손상된 진행 원장은 백업을 복구하고 원본을 .corrupt-시각 파일로 보존합니다.
  원본과 백업 모두 읽을 수 없으면 기록을 비우지 않고 서버 시작을 실패시킵니다.
- 백업/복원 시 월드와 플레이어 데이터, 양조/제련 블록 데이터, 주식 계좌를 같은 시점으로 관리해야 합니다.
